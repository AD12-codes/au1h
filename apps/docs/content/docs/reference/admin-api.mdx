title: Admin API
description: What the admin portal uses, available to scripts with an admin session.
---

All routes under `/api/v1` except `/health` require an **admin-portal session** (sign in
with `x-app-id: au1h-admin`) with an active workspace, or a personal access token, and are
scoped to that workspace. Unauthenticated calls get `401`; a client-application session
also gets `401`.

Scripts, CI and the `au1h` CLI authenticate with a
[personal access token](/docs/reference/tokens) instead:

```
Authorization: Bearer au1h_pat_…
```

## Workspace roles & permissions

Access within an admin workspace is role-based. Roles are stored on the workspace membership (`members` table) and evaluated on every request.

| Role | Access | Description |
| ---- | ------ | ----------- |
| `owner` | Read & Write | Full administrative access to workspace applications, proxy routes, API tokens, and users. |
| `admin` | Read & Write | Full administrative access to workspace applications, proxy routes, API tokens, and users. |
| `member` | Read-only | Can read all workspace resources (`GET`) and manage self-service personal access tokens, but cannot mutate workspace resources. |

### Role enforcement and 403 response

All mutating routes on workspace resources (applications, proxy routes, users) require the `owner` or `admin` role. If a caller with the `member` role attempts to invoke a restricted mutating route (via admin session or personal access token), the API refuses the request with `403 Forbidden`:

```json
{
  "error": "Requires the owner or admin role"
}
```

Personal access tokens (`/api/v1/tokens`) are self-service per-caller: any workspace member can create and revoke their own tokens for CLI and script use. The token live-inherits the caller's role, so a token minted by a member is strictly read-only on workspace resources. If a member's role changes, their existing tokens immediately reflect the new permissions without re-issuing the token. If the user is removed from the workspace, their tokens immediately return `401 Unauthorized`.

## Identity & workspace

| Endpoint       | Method | Description |
| -------------- | ------ | ----------- |
| `/api/v1/me`   | GET    | Returns identity, active workspace, resolved role (`owner`, `admin`, or `member`), and authentication method (`session` or `token`). |

Response:

```json
{
  "user": {
    "id": "usr_...",
    "email": "admin@example.com"
  },
  "organization": {
    "id": "org_...",
    "name": "Acme Corp",
    "slug": "acme-corp"
  },
  "role": "owner",
  "authVia": "session"
}
```

## Applications

| Endpoint                                     | Method | Role required | Body / notes                                    |
| -------------------------------------------- | ------ | ------------- | ----------------------------------------------- |
| `/api/v1/applications`                       | GET    | Any member    | List with user and session counts              |
| `/api/v1/applications/:id`                   | GET    | Any member    | Retrieve application details                   |
| `/api/v1/applications`                       | POST   | Owner, Admin  | `{ name, slug, allowedOrigins?, redirectUris?, logo? }` → `{ application, secret }` |
| `/api/v1/applications/:id`                   | PUT    | Owner, Admin  | Same fields plus `isActive`, `organizationsEnabled` |
| `/api/v1/applications/:id`                   | DELETE | Owner, Admin  | Delete application                             |
| `/api/v1/applications/:id/regenerate-secret` | POST   | Owner, Admin  | `{ secret }`, shown once                        |

`slug` is lowercase letters, digits and hyphens; `au1h-admin` is reserved.
`allowedOrigins` and `redirectUris` are comma-separated strings.

## Users

Users of your workspace's applications, plus your workspace's own members.

| Endpoint                                             | Method | Role required | Notes                                       |
| ---------------------------------------------------- | ------ | ------------- | ------------------------------------------- |
| `/api/v1/users?applicationId=&search=&page=&limit=`  | GET    | Any member    | Paginated user list                         |
| `/api/v1/users/:id`                                  | GET    | Any member    | User profile                                |
| `/api/v1/users/:id/sessions`                         | GET    | Any member    | Active user sessions                        |
| `/api/v1/users/:id/ban`                              | POST   | Owner, Admin  | `{ reason?, expiresAt? }`; revokes sessions |
| `/api/v1/users/:id/unban`                            | POST   | Owner, Admin  | Lift active ban                             |
| `/api/v1/users/:id/sessions`                         | DELETE | Owner, Admin  | Revoke all active sessions                  |
| `/api/v1/users/sessions/:sessionId`                  | DELETE | Owner, Admin  | Revoke single session                       |

## Proxy routes

| Endpoint                         | Method | Role required | Body                                                                      |
| -------------------------------- | ------ | ------------- | ------------------------------------------------------------------------- |
| `/api/v1/routes?applicationId=`  | GET    | Any member    | List proxy routes                                                         |
| `/api/v1/routes/:id`             | GET    | Any member    | Retrieve proxy route                                                      |
| `/api/v1/routes`                 | POST   | Owner, Admin  | `{ applicationId, name, pathPattern, backendUrl, methods, stripPrefix? }` |
| `/api/v1/routes/:id`             | PUT    | Owner, Admin  | Any of the above plus `isActive`                                          |
| `/api/v1/routes/:id/toggle`      | PATCH  | Owner, Admin  | `{ isActive }`                                                            |
| `/api/v1/routes/:id`             | DELETE | Owner, Admin  | Delete route                                                              |

The application must belong to your workspace. `backendUrl` must be `http(s)` without
credentials; private and loopback targets are refused in production.

## API tokens

Personal access tokens for CI, CLI, and scripts. Tokens inherit the caller's live role and are scoped to the caller's active workspace.

| Endpoint              | Method | Role required | Notes                                              |
| --------------------- | ------ | ------------- | -------------------------------------------------- |
| `/api/v1/tokens`      | GET    | Any member    | List active personal access tokens for caller      |
| `/api/v1/tokens`      | POST   | Any member    | `{ name, expiresInDays? }` (session auth required) |
| `/api/v1/tokens/:id`  | DELETE | Any member    | Revoke personal access token for caller            |
